# OctoAcme — Meeting Cadence Checklist

## Purpose
Define the recommended recurring meetings for a typical OctoAcme project so the team stays aligned, surfaces issues early, and avoids communication overload. Adapt the cadence to your team's size and working style.

---

## Recommended Meeting Cadence

### Daily Standup
- **Frequency:** Daily (or every working day the team agrees to)
- **Duration:** 15 minutes (strictly timeboxed)
- **Participants:** All delivery team members (Developers, Scrum Master/Delivery Lead, Tech Lead)
- **Facilitator:** Scrum Master / Delivery Lead
- **Agenda:**
  - What did I complete since last standup?
  - What will I work on today?
  - Are there any blockers or dependencies I need help with?
- **Outputs:** Updated project board; blockers logged for follow-up

### Weekly PM + PdM Sync
- **Frequency:** Weekly
- **Duration:** 30–45 minutes
- **Participants:** Project Manager, Product Manager
- **Agenda:**
  - Status against milestones
  - Risk register review
  - Backlog and priority updates
  - Upcoming stakeholder communication needs
- **Outputs:** Updated risk register; stakeholder update drafted if needed

### Sprint Planning
- **Frequency:** Start of each sprint (typically every 1–2 weeks)
- **Duration:** 1–2 hours depending on sprint length
- **Participants:** Full delivery team + Product Manager
- **Facilitator:** Scrum Master / Delivery Lead
- **Agenda:**
  - Review sprint goal
  - Pull backlog items into the sprint; confirm acceptance criteria
  - Confirm team capacity and identify any risk to the sprint goal
- **Outputs:** Committed sprint backlog; updated project board

### Sprint Review / Demo
- **Frequency:** End of each sprint
- **Duration:** 30–60 minutes
- **Participants:** Delivery team, Product Manager, Project Manager, optional stakeholders
- **Facilitator:** Product Manager or Scrum Master
- **Agenda:**
  - Demo completed work
  - Gather feedback from stakeholders
  - Review sprint metrics (velocity, burndown)
- **Outputs:** Feedback captured; backlog updated; stakeholders informed of progress

### Retrospective
- **Frequency:** End of each sprint or milestone
- **Duration:** 45–75 minutes
- **Participants:** Delivery team (+ PM when useful)
- **Facilitator:** Scrum Master / Delivery Lead
- **Agenda:**
  - What went well?
  - What could be improved?
  - Agree on 2–3 action items with owners and due dates
  - Review previous action items
- **Outputs:** Action items added to backlog; retrospective notes stored in project repo

### Monthly Stakeholder Update
- **Frequency:** Monthly (or at major milestones)
- **Duration:** 30–45 minutes
- **Participants:** Project Manager, Product Manager, key stakeholders, sponsor
- **Agenda:**
  - Progress against roadmap and milestones
  - Risks and dependencies requiring stakeholder awareness or decision
  - Upcoming releases and customer impact
  - Any asks or approvals needed
- **Outputs:** Updated stakeholder status report; decisions or approvals documented in decision log

### Release Readiness Review
- **Frequency:** Before each planned release
- **Duration:** 30–60 minutes
- **Participants:** Project Manager, Tech Lead, Release Manager, QA, Product Manager, Security Champion (if security changes involved)
- **Agenda:**
  - Confirm all acceptance criteria and pre-release requirements are met
  - Review release notes and rollback plan
  - Confirm deployment window and on-call coverage
  - Final sign-off from each role
- **Outputs:** Release go/no-go decision documented; release notes approved

---

## Meeting Setup Checklist

- [ ] All recurring meetings are scheduled in team calendars with recurring invites
- [ ] Each meeting has a named facilitator and a shared agenda template
- [ ] Meeting notes and action items are captured and stored (project repo, wiki, or shared doc)
- [ ] Participants know which meetings they are required vs. optional for
- [ ] Meeting cadence has been reviewed with the team and adjusted to fit team size and pace
- [ ] Calendar invites include a link to the relevant doc (e.g., backlog, risk register, decision log)

---

## Meeting Checklist by Phase

### Initiation Phase
- [ ] Kickoff meeting held with all key stakeholders and delivery team
- [ ] RACI reviewed and agreed (see [RACI Template](octoacme-raci-template.md))
- [ ] Recurring cadence scheduled for the project duration

### Planning Phase
- [ ] Sprint planning cadence confirmed
- [ ] Risk review cadence confirmed with Project Manager
- [ ] First stakeholder update scheduled

### Execution Phase
- [ ] Daily standups running and timeboxed
- [ ] Sprint reviews scheduled with stakeholders invited
- [ ] Retrospectives scheduled with all delivery team members

### Release Phase
- [ ] Release readiness review scheduled at least one week before deployment window
- [ ] Post-release review / retrospective scheduled

### Close & Retrospective
- [ ] Final project retrospective scheduled
- [ ] Recurring meetings cancelled or transitioned to maintenance cadence
